# pi-agent-server 项目文档

基于 **Pi（pi-coding-agent）SDK 同进程嵌入**（报告路线 A）实现的编码智能体 HTTP 服务。

- 技术栈：Node.js + TypeScript（tsx 运行）
- Agent 引擎：`@earendil-works/pi-coding-agent` SDK
- 服务端：Node 原生 `http`（零第三方 Web 框架）+ SSE 流式
- 目标：把 Pi 作为可编程 HTTP 服务，供其他应用/前端/脚本接入

## 1. 项目结构

```
pi-agent-server/
├── config/
│   ├── server.json              # 服务配置（端口/工作目录/默认模型/工具）
│   └── providers.json           # 供应商/模型/Key 配置（Pi models.json 原生格式）
├── data/                        # 运行时数据（自动生成，.gitignore 忽略）
│   ├── agent/                   # auth.json、models-store.json（凭据/模型目录缓存）
│   └── sessions/                # 会话 JSONL 落盘文件
├── src/
│   ├── server.ts                # HTTP 服务 + SSE + 路由
│   ├── agent-manager.ts         # 多会话管理 + 模型切换 + 持久化
│   ├── providers.ts             # 供应商配置文件读写 + 校验 + 脱敏
│   └── config.ts                # 服务配置加载 + 路径解析
├── package.json
├── tsconfig.json
├── README.md
└── 项目文档.md                  # 本文件
```

分层依赖（自下而上）：

```
Pi SDK (createAgentSession / ModelRuntime / SessionManager)
   └─ AgentManager        多会话生命周期、模型切换、供应商热重载
        └─ server.ts      HTTP 路由 + SSE 事件转发 + provider 管理 API
```

## 3. 启动方式

### 3.1 首次安装

```bash
cd pi-agent-server
npm install
```

### 3.2 启动 / 开发

```bash
npm start        # 前台启动（tsx src/server.ts）
npm run dev      # 监听模式，代码/配置变更自动重启
npm run typecheck # 类型检查（tsc --noEmit）
```

启动成功后输出：

```
pi-agent-server listening on http://127.0.0.1:8787
  workspace : D:\MyAPP\agent
  sessions  : ...\data\sessions
  providers : config/providers.json (edit + auto hot-reload via /api/providers)
```

默认监听 `http://127.0.0.1:8787`。

### 3.3 后台运行（Windows PowerShell）

```powershell
Start-Process -FilePath "cmd" -ArgumentList "/c npm start > server.log 2>&1" `
  -WorkingDirectory "pi-agent-server" -WindowStyle Hidden
```

停止：结束占用 8787 端口的进程，或对进程发送 `SIGINT`/`SIGTERM`（会先 `disposeAll()` 优雅关闭会话）。

## 4. 配置说明

### 4.1 `config/server.json`

| 字段 | 类型 | 说明 |
|---|---|---|
| `host` | string | 监听地址，默认 `127.0.0.1` |
| `port` | number | 监听端口，默认 `8787` |
| `workspaceDir` | string | agent 工具的**工作目录**（文件操作作用域），相对路径基于项目根 |
| `sessionDir` | string | 会话 JSONL 落盘目录，默认 `data/sessions` |
| `agentDir` | string | 隔离的 Pi 配置目录，默认 `data/agent` |
| `defaultModel` | `{provider, id}` | 新会话默认模型，不配置则取「首个可用模型」 |
| `thinkingLevel` | string | 默认思考等级：`off/minimal/low/medium/high/xhigh/max` |
| `tools` | string[] | 启用工具白名单：`read/powershell/bash/edit/write/grep/find/ls` |

### 4.2 `config/providers.json`（供应商 / 模型 / Key）

采用 Pi 原生 `models.json` 格式，**不使用环境变量**。直接编辑文件或用 `/api/providers` 接口增删改，改动即时热生效（与 Pi 的 `/model` 同机制，无需重启）。

```jsonc
{
  "providers": {
    "deepseek": {
      "name": "DeepSeek Official",
      "baseUrl": "https://api.deepseek.com",
      "api": "openai-completions",           // OpenAI 兼容中转站均用此值
      "apiKey": "sk-...",
      "compat": {
        "supportsDeveloperRole": false,
        "supportsReasoningEffort": false,
        "maxTokensField": "max_tokens"
      },
      "models": [
        { "id": "deepseek-chat", "name": "DeepSeek Chat (V3)", "reasoning": false, "input": ["text"], "contextWindow": 65536, "maxTokens": 8192 },
        { "id": "deepseek-reasoner", "name": "DeepSeek Reasoner (R1)", "reasoning": true, "input": ["text"], "contextWindow": 65536, "maxTokens": 8192 }
      ]
    }
  }
}
```

字段说明：

- `baseUrl`：API 端点地址；OpenAI 兼容中转站填其根地址（如 `https://relay.example.com/v1`）。
- `api`：流式实现类型，OpenAI 兼容一律用 `openai-completions`。
- `apiKey`：支持 Pi 值语法——字面量 `sk-...`、环境引用 `$VAR` / `${VAR}`、命令执行 `!command`。
- `compat`：兼容开关，常用 `supportsDeveloperRole:false`（强制 `system` 角色）、`supportsReasoningEffort:false`、`maxTokensField:"max_tokens"`。
- `models`：模型列表，`id` 必填，其余（`reasoning`/`input`/`contextWindow`/`maxTokens`/`cost`）可选。

> 安全提示：Key 明文存于该文件，注意仓库/文件权限；服务端 API 响应中 Key 一律脱敏。

## 5. 接口信息

Base URL：`http://127.0.0.1:8787`

### 5.1 通用

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | API 概览（JSON） |
| GET | `/api/health` | 健康检查，返回 `{ok, uptime}` |

### 5.2 供应商 / 模型管理

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/providers` | 供应商列表（key 脱敏，含 `hasApiKey`、`apiKeyMasked`） |
| PUT | `/api/providers/:id` | 新增或整体替换供应商，体：`{name?, baseUrl, api?, apiKey?, compat?, models[]}` |
| PATCH | `/api/providers/:id` | 部分更新（如只换 `apiKey`）；`apiKey:null` 删除 key |
| DELETE | `/api/providers/:id` | 删除供应商 |
| GET | `/api/models` | 全部模型 + `available`（是否已配置可用 key）+ `source`（`providers.json`/`builtin`） |

> 供应商 `id` 仅允许 `[a-zA-Z0-9][a-zA-Z0-9_-]*`。PUT/PATCH/DELETE 后立即 `refreshProviders()` 热重载，无需重启。

### 5.3 会话管理

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/sessions` | 新建会话，体：`{name?}` |
| GET | `/api/sessions` | 会话列表（落盘文件：`id/name/file/created/modified/messageCount/isOpen`） |
| GET | `/api/sessions/:id` | 会话详情（模型、thinking、工具、空闲态；`availableThinkingLevels` 为该模型支持的思考等级） |
| DELETE | `/api/sessions/:id` | 关闭会话（释放内存，保留落盘文件） |
| GET | `/api/sessions/:id/messages` | 完整消息历史（含 `model`、`thinkingLevel`、`availableThinkingLevels`） |
| GET | `/api/sessions/:id/stats` | token / 成本统计 |

会话 ID 示例：`01a09082-d6e7-712e-99d1-10766d6d50ae`。重启后会话仍在磁盘，可用任意 `GET /api/sessions/:id` 重新打开并续聊。

### 5.4 对话

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/sessions/:id/prompt` | 发送消息。默认 **SSE 流式**；体：`{message, stream?, streamingBehavior?, images?}` |
| POST | `/api/sessions/:id/abort` | 中止当前 run |
| POST | `/api/sessions/:id/compact` | 上下文压缩，体：`{instructions?}` |

`prompt` 请求体：

```jsonc
{
  "message": "列出当前目录的文件",
  "stream": true,                 // 默认 true（SSE）；false 则同步返回 JSON
  "streamingBehavior": "steer"    // 繁忙时排队：steer（插队）/ followUp（等待）
}
```

- 会话空闲时无 `streamingBehavior` 直接执行；繁忙时缺省返回 `409`。
- `stream:false` 时返回：`{sessionId, model, messages, lastAssistantText}`。

### 5.5 模型 / 思考切换

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/sessions/:id/model` | 切换模型（同 Pi `/model`）。体：`{provider, id, thinkingLevel?}`，或 `{action:"cycle"}`（同 Ctrl+P 循环）。返回 `model`、`thinkingLevel`、`availableThinkingLevels` |
| POST | `/api/sessions/:id/thinking` | 设置思考等级，体：`{level}`；仅接受当前模型支持的等级，返回 `thinkingLevel`、`availableThinkingLevels` |

切换成功后立即生效，可直接续聊（Pi 支持跨供应商上下文交接）。

## 6. SSE 事件流

`POST /api/sessions/:id/prompt`（`stream` 未关）返回 `text/event-stream`，每条 `event:<类型>\ndata:<JSON>\n\n`：

```
open
agent_start
message_start
message_update        # 增量：text_delta / thinking_delta / toolcall_start/delta/end
tool_execution_start  # 工具开始（工具名 + 入参）
tool_execution_update # 工具流式输出
tool_execution_end    # 工具结束（结果 + isError）
message_end           # message 为权威最终消息
turn_end
agent_end
agent_settled         # 彻底安定（无任何自动后续）
done                  # 服务端发起，收起：{sessionId, settled}
```

事件名等于 JSON 内 `type` 字段，客户端按 `type` 分发即可。`message_update` 已剔除 `partial` 大对象，仅保留 `{type, contentIndex, delta?, content?}`。

客户端断开连接会中止当前 run。

## 7. 典型调用示例

### 7.1 新建会话并流式对话

```bash
# 新建会话
curl -s -X POST localhost:8787/api/sessions \
  -H "Content-Type: application/json" -d '{"name":"demo"}'
# => {"id":"xxx","model":"deepseek/deepseek-chat",...}

# SSE 流式对话（-N 禁用缓冲）
curl -N -X POST localhost:8787/api/sessions/<id>/prompt \
  -H "Content-Type: application/json" \
  -d '{"message":"列出当前目录的文件"}'
```

### 7.2 非流式（取最终回复）

```bash
curl -s -X POST localhost:8787/api/sessions/<id>/prompt \
  -H "Content-Type: application/json" \
  -d '{"message":"用一句话总结","stream":false}'
# => {"messages":[...],"lastAssistantText":"..."}
```

### 7.3 切换模型 + 思考

```bash
# 切到 DeepSeek R1 并开 medium 思考
curl -s -X POST localhost:8787/api/sessions/<id>/model \
  -H "Content-Type: application/json" \
  -d '{"provider":"deepseek","id":"deepseek-reasoner","thinkingLevel":"medium"}'

# 循环切换（同 Ctrl+P）
curl -s -X POST localhost:8787/api/sessions/<id>/model \
  -H "Content-Type: application/json" -d '{"action":"cycle"}'
```

### 7.4 新增一个 OpenAI 兼容中转站（立即生效）

```bash
curl -s -X PUT localhost:8787/api/providers/my-relay \
  -H "Content-Type: application/json" -d '{
    "baseUrl": "https://relay.example.com/v1",
    "api": "openai-completions",
    "apiKey": "sk-xxx",
    "compat": {"supportsDeveloperRole": false},
    "models": [{"id": "gpt-4o", "reasoning": false}]
  }'

# 仅换 Key / 删 Key
curl -s -X PATCH localhost:8787/api/providers/my-relay \
  -H "Content-Type: application/json" -d '{"apiKey":"sk-new"}'

# 删除供应商
curl -s -X DELETE localhost:8787/api/providers/my-relay
```

### 7.5 会话历史与统计

```bash
curl -s localhost:8787/api/sessions/<id>/messages
curl -s localhost:8787/api/sessions/<id>/stats
```

## 8. 注意事项

1. **并发**：一个会话同一时刻只跑一个 agent run；多用户请各用独立会话。
2. **工具权限**：`tools` 为白名单，生产环境可只给只读工具（`read/grep/find/ls`）或配合沙箱。
3. **Key 安全**：Key 明文存于 `config/providers.json`，务必管控文件与仓库权限；API 响应已脱敏。
4. **供应商热重载**：PUT/PATCH/DELETE 后 `ModelRuntime.refresh({allowNetwork:false})` 即时生效；正在使用的旧模型对象不受影响，切走后即失效。
5. **超时**：模型 API 请求由 Pi 内部处理，服务端无额外超时；SSE 断开会触发 abort。
6. **升级兼容**：依赖 `@earendil-works/pi-coding-agent` 公共导出（`createAgentSession`/`ModelRuntime`/`SessionManager`/`SettingsManager`），升级时留意大版本 API 变化。
